# OWN STREET 채팅 화면 — 컴포넌트 규칙

`app/styles.css`, `app/app.js`(채팅 화면, 10-15 developer 이식)를 2026-10-16 디자이너가 다듬으면서
정리한 기준. 다음에 채팅 안에 새 카드·버튼을 추가할 때 이 규칙을 먼저 본다.

## 색·테두리·그림자 (바뀌지 않음)
- 배경 `--background` #F6F3ED / 글자 `--foreground` #13161B / 포인트 `--accent` #F85003
- 카드 배경은 `--card`(#FCFAF6, 배경보다 살짝 밝음)를 쓴다. 배경과 같은 색을 쓰면 테두리만으로 구분해야 해서 약하다.
- 테두리는 2px, 강조 그림자는 4px 오프셋(`4px 4px 0 0 var(--foreground)`). 완료 카드처럼 "가장 중요한 카드"는 그림자 색만 `--accent`로 바꿔 구분한다(`.done-card`).
- 작은 요소(칩, 로그인 상태 배지)는 그림자를 더 얇게(2~3px) 써서 위계를 낮춘다.

## 말풍선(`.bubble`) vs 카드(`.card.wide`)
- **말풍선**: 봇/손님의 짧은 대화 한 마디. `max-width: 88%`, 테두리만 있고 그림자 없음. 좌우 정렬로 발화자를 구분한다(봇 왼쪽/`--card` 배경, 손님 오른쪽/`--foreground` 배경).
- **카드**(`msg.wide` + `.card`): 사이즈 선택 결과, 주문 확인, 접수 완료, 결제 안내, 목업처럼 "손님이 다시 눌러야 하거나 다시 봐야 하는 덩어리 정보"에만 쓴다. 폭을 100%로 넓히고 그림자를 준다. 말풍선보다 무거운 요소이므로 남발하지 않는다 — 한 번의 질문-답에는 말풍선, 결과·확인에는 카드.
- 지나간 확인 카드는 `retireCards()`가 `.is-old`(그림자 제거 + 반투명)로 바꾼다. 새 카드가 분명히 "지금 활성화된 것"으로 보이게 하기 위함이다. 새 카드 종류를 추가해도 되돌아갈 수 있는 카드라면 이 패턴을 따른다.

## 버튼 크기 (엄지 기준)
- 모든 누르는 요소는 최소 **48px 높이**를 지킨다: `.send`, `.composer .own-input`, `.choice`. 글자만 있는 링크형 버튼(`.link`, `.is-ghost`)은 예외지만 상하 여백으로 탭 영역을 넓힌다.
- 주요 행동 버튼(`주문하기`, `카카오페이로 결제하기`)은 폭 100% + `padding: 16px 24px` 로 화면에서 가장 크게 둔다. 그 다음 중요도는 `.choice.is-primary`(오렌지 배경), 그 다음은 일반 `.choice`(흰 배경 + 테두리), 가장 낮은 것은 `.is-ghost`(밑줄만).
- 사이즈 칩(`.choice.is-size`)은 숫자/영문 한 글자~세 글자라 `min-width: 58px` 로 정사각형에 가깝게 눌러도 손가락이 안 겹치게 한다.

## 색 사용 규칙
- 오렌지(`--accent`)는 "지금 눌러야 하는 것·가장 중요한 숫자"에만 쓴다: 주 행동 버튼, 결제 금액, 진행 막대, 섹션 번호(`01`). 한 화면에 오렌지가 너무 많아지면 무엇이 중요한지 흐려지므로 카드 안에서 1곳을 넘기지 않는다.
- **"카드당 오렌지 1곳" 규칙은 카드의 그림자와는 별개로, 카드 안 텍스트/아이콘 색으로 셀 때도 적용된다.** `.done-card`는 그림자 색을 `--accent`로 바꿔 "가장 중요한 카드"임을 표시하지만, 카드 안에도 이미 `.modal-kicker`("REQUEST COMPLETE" + 점)가 오렌지 글자색을 쓰고 있다 — 이게 그 카드의 "내용 오렌지 1곳"이다. 같은 카드 안에 추가로 오렌지 글자색을 쓰는 라벨이나 강조를 넣지 않는다(10-18 디자이너가 `.done-story-label`로 실제 발견·수정, 아래 참고).
- `.done-story-label`("당신의 스트릿")은 `--accent`가 아니라 `--muted-foreground`를 쓴다. 처음엔 오렌지로 추가됐는데, 실제로 렌더링해보니 같은 카드 안 `.modal-kicker`와 함께 오렌지가 2곳(+그림자까지 3곳)이 되어 "가장 중요한 게 뭔지" 흐려졌다. 작은 대문자 + `letter-spacing: 0.08em`으로 색 없이도 "라벨"로 읽히게 하고, 바로 위 "접수번호" 라벨(`.modal-sub`, 역시 muted-foreground)과 톤이 맞아 카드 안 라벨들이 일관되게 보인다.
- 경고/오류는 `--destructive`(빨강 계열), 상태 안내(느림·확인 중)는 `--muted-foreground` + 점선 테두리(`.msg.status`). 둘을 섞지 않는다.

## 한글 vs Anton
Anton은 영문 전용 디스플레이 폰트라 한글을 넣으면 Pretendard로 자동 대체되면서 다른 글꼴보다 가늘어 보인다.
- 섹션 제목처럼 **영문 대문자**로만 쓰는 자리는 `.font-display`(Anton) 그대로 쓴다.
- **한글 버튼/라벨**은 `.font-sans` 계열을 굵게(`font-weight: 700~800`) 써서 선명하게 만든다. 이미 있는 예: `.btn-label-ko`, `.btn-request-ko`, 그리고 오늘 추가한 `.order-row dt.order-label-ko`(주문 확인 카드의 "이미지 링크" 같은 한글 라벨 — 이전에는 `.font-display`를 그대로 써서 다른 한글 글자보다 가늘어 보였다).
- 숫자·접수번호(`OS-0001`)처럼 **영문+숫자 조합**은 Anton 그대로 둬도 된다(지금처럼).

## 진행 표시 — 숫자 대신 막대
- `#topProgress`(`.topbar-progress`)가 상단 바 바로 아래, 2px 테두리 안쪽에 3px 높이로 붙는다.
- **숫자(3/8)를 쓰지 않는다.** 건너뛰기(`story`, `memo`)·수정(확인 카드에서 되돌아가기)이 있어서 "지금 몇 번째 질문"이라는 숫자가 실제와 어긋날 수 있다(10-15 developer 가 지적, 10-16 디자이너 판단 — 숫자는 넣지 않는 게 맞다고 결론).
- 대신 `setProgress(idx)`가 `idx / STEPS.length` 비율만큼 막대를 채운다. 이 비율은 "정확한 단계 수"를 주장하지 않고 "꽤 왔다/얼마 안 왔다" 정도의 방향감만 준다. 수정하러 되돌아가도 막대가 줄었다 늘었다 하는 게 틀린 게 아니라 자연스럽다 — 숫자처럼 "정답이 있는 값"이 아니기 때문이다.
- 접수가 끝나면(`showComplete`) `hideProgress()`로 막대를 치운다. 완료 화면은 더 이상 "진행 중"이 아니다.

## 티셔츠 뒷면 목업 자리
- `app/assets/tee-back-mockup.svg` — 뒷면 아웃라인 + 점선 프린트 영역(`최대 A3`)만 보여주는 정적 SVG. `buildMockupCard()`(`app/app.js`)가 접수 완료 카드 바로 다음에 추가한다.
- **손님이 생성한 이미지를 직접 끌어와 보여주지 않는다.** 손님이 보내는 것은 PNG 파일 주소가 아니라 "이미지가 있는 채팅 링크"(예: 생성형 AI 채팅 공유 링크)라서, 신뢰할 수 없는 외부 주소를 그대로 `<img src>`에 걸 수 없다(접속이 로그인 페이지로 튈 수도 있고, 이미지가 아닐 수도 있다). 그래서 지금은 "어디에 어떤 크기로 인쇄되는지"만 보여주는 자리이고, 실제 이미지를 넣으려면 손님이 올린 이미지 파일 자체를 받는 절차가 따로 필요하다 — 이건 디자이너 권한 밖의 구조 변경이라 developer/브랜더 논의로 남긴다.
- 자리를 더 쓰게 된다면(예: 앞면 추가, 색상별 티셔츠) 같은 SVG 파일에 뷰를 늘리는 대신 `tee-front-mockup.svg` 처럼 파일을 나눠 추가하고 `buildMockupCard()`에 타입 인자를 넘기는 방식을 권장한다.

## 자주 쓰는 카드 레이아웃
- `.mockup-card`, `.pay-card`: `display: grid; gap: 10px; justify-items: center; text-align: center;` — 중앙 정렬형 정보 카드의 공통 패턴. 새 "정보 보여주기 전용" 카드를 추가할 때 이 패턴을 재사용한다.
- `.order-card`: 좌측 라벨 + 우측 값 + 수정 버튼의 3열 그리드(`76px 1fr auto`). 항목을 나열하고 각 항목을 수정할 수 있어야 하는 카드에 재사용한다.
