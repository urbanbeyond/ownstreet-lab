## 세 의견의 합의와 이견
**합의 (세 명 모두)**
- 의장 방향에 따라 채팅을 최종 모습으로 한다. 지난 10-08 결정(서버 먼저, 질문 순서는 가설)과 충돌하지 않는다. 오히려 같은 방향이 더 분명해졌다.
- 하단 고정 입력창, 질문 종류별로 바뀌는 입력 영역, 접수번호는 서버가 저장을 확인한 응답 뒤에만 보이는 카드.
- 첫 질문에서 손님의 말을 말풍선에 그대로 되돌려 보여 주는 것이 선언문에 가장 가까운 첫 걸음.
- 말풍선·카드·칩의 공통 규칙이 먼저 있어야 네이밍·로고·브랜드 카드가 한 서비스로 보인다.
- 손님 단위 저장소는 플랫폼에 필요하지만 의장 결정 사항이다.

**이견과 내 결정**
1. 진행 단계 점("3/8") — 진 디자이너 제안, 윤 개발자는 건너뛰기·되돌리기로 숫자가 틀릴 수 있다고 보완. **결정:** 총 단계 수를 상수로 고정하고, 건너뛴 단계도 숫자에 센다. 숫자가 틀릴 위험이 크면 점 표시를 빼고 상단 바는 로고와 로그인 상태만 둔다. 윤 개발자가 구현하며 판단.
2. 로그인 위치 — 윤 개발자는 인앱 브라우저(인스타·카카오톡)에서 Google 로그인이 막히므로 첫 말풍선에 "외부 브라우저로 열기" 안내가 필요하다고 함. 신 브랜더의 취향 질문은 첫 질문이다. **결정:** 첫 화면은 취향 질문 말풍선이 먼저 나오고, 로그인은 이름 질문 앞(접수에 꼭 필요해지는 시점)에 둔다. 인앱 브라우저 안내는 로그인 단계 말풍선에 둔다. 로그인 없이도 대화가 시작되므로 인앱에서 첫 단계부터 막히지 않는다. 단, 이 순서는 이탈 기록이 없는 가설이다.
3. "이미지 있어요/없어요" 갈림길 — 신 브랜더가 네이밍이 없는 동안 "없어요"가 막다른 길이라고 지적. **결정:** 네이밍이 만들어지기 전에는 갈림길을 만들지 않는다. 첫 질문은 이미지 링크 하나로 시작하고, 칩 2개 안은 Stage 2 에서 다시 본다. (진 디자이너 안의 칩 2개는 보류.)
4. 일정 — 윤 개발자는 "하루에 다 못 한다, 3일 이상"으로 봄. **결정:** 받아들인다. 로직 이식 → 화면 골격 → 시험·수정으로 나눈다.
5. 기존 폼 — 윤 개발자는 LAB 에서만 폼을 잠시 남기자고 함. **결정:** 비교용으로 `app/` 에 남기지는 않는다(파일이 둘이면 LIVE 승격 때 사고 위험이 있다). 폼은 git 기록과 현재 LIVE 에 그대로 있으므로 되돌릴 수 있다.

## 안전장치 (그대로 유지, 이번 방향 변경으로 바뀌는 것 없음)
- 가짜 로그인·가짜 성공·임의 접수번호를 만들지 않는다. 접수번호(OS-…)는 서버가 저장을 확인한 응답(`ok:true`, `v>=2`, OS- 형식) 뒤에만 말풍선에 보인다. 응답이 없으면 성공 말풍선을 만들지 않고 "확인 중/확인하지 못했습니다"로 보인다.
- v0.2 의 안전장치(60초 기다림, 10초 안내, 답 없을 때 같은 clientRef 로 다시 확인, `NOT_SAVED_CODES` 구분, 토큰 새로 받아 재시도)는 채팅으로 옮길 때 "보내기" 함수는 건드리지 않고 화면만 말풍선으로 바꾼다.
- LAB/LIVE 분리: 모든 작업은 LAB 으로만 나간다. LIVE 는 의장이 버튼을 눌러야만 바뀐다. LIVE 서버 반영이 먼저, `Promote LAB to LIVE` 는 맨 마지막(OPERATOR_TODO 의 기존 주의 그대로).
- `config.js` 의 `requestEndpoint`, `firebase`, `payment.kakaopayLink`, `contactUrl`, `kakaopay-qr.svg` 는 바꾸지 않는다.
- 개인정보는 `sessionStorage` 에만 두고 로그아웃 때 지운다. 코드·로그·기록에 넣지 않는다.
- 외부 AI API 를 새로 붙이지 않는다(네이밍은 규칙·사전 기반).
