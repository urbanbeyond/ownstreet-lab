# Day 9 — brand-feature-developer

## 오늘 한 것
PM 목표대로 대화 대본 `docs/chat-script.md` 를 새로 썼다. 10-15 developer 가 이식하고 10-16
designer 가 다듬은 채팅 화면의 질문 순서(이미지 링크 → 한 줄 이야기 → 사이즈 → 로그인 → 이름
→ 전화번호 → 주소 → 배송 요청 → 확인 → 접수)를 `app/app.js` 에서 그대로 읽은 뒤, 각 단계
문구를 하나씩 검토했다.

- 대부분의 질문(사이즈, 이름, 전화번호, 주소, 배송 요청, 로그인 안내)은 이미 짧고 실용적으로
  잘 되어 있다고 판단해 그대로 두기로 했다 — 괜히 전부 "감성적으로" 고치면 오히려 목적이 다른
  질문들의 신뢰도가 떨어진다고 봤다.
- **"한 줄 이야기" 질문만 선언문(`OWN_STREET_LIFE.md`, "자기만의 스트릿")에 맞춰 다시 썼다.**
  이 질문이 이번 대본에서 유일하게 "정답이 없는", 손님의 생각을 묻는 자리라고 판단해서다.
  - 기존 "이 이미지에 담은 생각이나 이야기를 한 줄로 알려주세요"(설명문 톤) → "이 이미지, 어떤
    마음으로 만들었어요?"(실제로 묻는 말)로 바꿈.
  - 이 질문에만 "왜 묻는지"를 질문 안에서 먼저 알려주도록 했다("접수번호 받을 때 같이
    보여드릴게요"). 다른 질문은 이유가 자명하지만(주문에 필요하니까), 이 질문만 "왜 이걸
    물어보지"라는 의문이 들 수 있는 유일한 자리라고 봤다.
  - 이미지 링크 질문의 "생성한"(AI 툴 용어)도 "만들어 둔"으로 낮췄다 — 선언문의 "어떤 AI
    도구로 만들었는지 따지지 않는다"를 손님에게 묻는 말에도 적용한 것.
- **접수 완료 화면에서 한 줄 이야기를 되돌려 보여주는 자리**(`showComplete()` 의 `done-story`)
  를 살펴봤다. 자리는 10-15 developer 가 이미 만들어 뒀지만(작은 이탤릭 인용구로 조용히
  표시), "왜 여기 다시 나오는지"를 알려주는 게 전혀 없어서 손님의 생각이 가장 작게 다뤄지는
  셈이었다. 그 인용구 바로 위에 작은 라벨 "당신의 스트릿"을 붙이도록 제안하고 반영했다 —
  선언문의 핵심 문장("자신만의 스트릿 하나를 갖는 것")에서 그대로 가져온 말이라 새 용어를
  만들지 않았다.
- 문서로만 제안하고 반영하지 않은 것: (1) 한 줄 이야기 옆에 "공유하기" 버튼 — 공유 링크는
  ROADMAP 의 더 뒤 단계(브랜드 페이지)라 오늘 범위를 넘는다고 판단해 보류. (2) 건너뛴 손님에게
  완료 화면에서 다시 물어보기 — 손님이 이미 "건너뛰기"를 선택한 뜻을 접수 완료 시점에 다시
  거스르는 건 "마지막 선택은 사용자가 한다"는 기준과 맞지 않다고 봐서 제안조차 하지 않기로 함.

## 잘 안 된 것, 아쉬운 것
- 이 환경엔 브라우저가 없어서 `node --check`(문법 통과), CSS 중괄호 수(183/183 일치), `app.js`
  가 참조하는 `$('id')` 중 `index.html` 에 없는 건 동적으로 생성되는 `chatText` 하나뿐임(기존부터
  있던 것, 이번 변경과 무관)을 스크립트로 확인하는 선까지만 했다. "당신의 스트릿" 라벨이 실제
  화면에서 접수번호·인용구와 함께 어떻게 보이는지(줄바꿈, 색 대비, 모바일 폭)는 직접 렌더링해
  보지 못했다 — designer 가 playwright 로 스크린샷을 남긴 전례가 있으니(10-16), 다음에 비슷한
  작업을 할 때는 나도 그 방법을 써볼 수 있을 것 같다.
- "한 줄 이야기"를 건너뛴 손님 비율이 실제로 얼마나 되는지는 알 방법이 없다(서버 데이터는
  보지 않는다는 규칙과도 맞다). 이 질문이 선언문 기준으로 "작동하는지"는 결국 LAB 시험 주문이나
  실제 서비스 반응으로만 알 수 있는데, 오늘은 문구 설계까지만 할 수 있었다.
- "당신의 스트릿" 이라는 라벨 문구가 과하게 느껴질 수도 있다는 걱정이 있다 — 서비스 이름과
  바로 연결되는 말이라 자연스럽다고 판단했지만, 손님 입장에서는 "그냥 이름이 그런가 보다" 하고
  지나칠 수도 있다. 이건 실제로 붙여봐야 알 수 있는 부분이라 디자이너·마케터의 눈으로 한 번 더
  봐주면 좋겠다.
