# Day 15 — PM 결정
- 오늘의 역할: developer
- 오늘 목표: `app/app.js` 의 "이어하기(resume)" 기능이 실제로는 전혀 동작하지 않는 버그를 고친다. `init()`(68행)이 파일 맨 위에서 즉시 호출되는데, `init() → initChat() → loadDraft()` 경로가 246행에서 선언되는 `const QUESTIONS` 를 그보다 먼저(선언 전) 참조해 `Cannot access 'QUESTIONS' before initialization` 예외가 나고, `loadDraft()` 의 `try/catch` 가 이를 조용히 삼켜 매번 `null` 을 반환한다. 결과적으로 손님이 답변 중 탭을 닫았다가 같은 세션에서 다시 열어도 처음부터 다시 질문이 시작된다. 10-22 developer 가 제안한 방법(설정 상수 선언을 `init()` 호출보다 앞으로 옮기거나 `init()` 호출 위치를 파일 끝으로 이동)대로 선언 순서만 바꿔 고치고, Playwright 로 "진행 중 세션을 끊고 다시 열면 이어하기 메시지가 뜨고 답변이 복원되는지"를 수정 전/후로 실제 확인한다. 서버(Code.gs)는 건드리지 않는다.
- 이유: DIRECTION.md 에 미처리 지시 없음(전부 ✅, 10-23 운영 항목 2건은 Firebase 허용 도메인·https 인증서로 의장 손이 필요한 일이라 OPERATOR_TODO 에 이미 있음). LAB 상태는 10-22 기준 정상. ROADMAP 의 밀린 시험·수정(#7, #8)은 10-20·10-21 에 끝났고 다음 회의(10-26, 월)까지는 평일 작업일이다. 이번 건은 "사흘 넘게 쉰 역할"이나 "반복되는 댓글 요청"보다 우선순위가 높다 — 10-22 developer 가 어제 바로 발견해 구체적인 재현 방법과 고치는 방법까지 적어 둔, 실제 손님이 겪을 수 있는 숨은 버그이기 때문이다(판단 기준 2·3번보다 "실제로 깨진 기능을 고친다"가 먼저라고 봤다). 코드 한 곳의 선언 순서만 옮기는 작업이라 하루 안에 끝나고, 서버 배포가 필요 없어 의장 손을 기다리지 않고 바로 LAB 에 반영할 수 있다.
- 팀원 의견 반영: 윤 개발자(10-22 work_summary, "다음에 이어서 할 것") — "`init()`/`QUESTIONS` 선언 순서 버그를 다음 평일 작업으로 수정하는 것을 제안한다(PM 판단 필요). 코드만 옮기면 되는 간단한 수정으로 보이고, 서버 배포 없이 LAB 반영만으로 고칠 수 있다"고 남긴 것을 오늘의 목표로 그대로 채택했다. 같은 날 "팀원에게 한마디"에서 진 디자이너에게 "탭을 닫았다 다시 열기 케이스도 한 번 눈으로 봐주시면 좋겠다"고 부탁했는데, 이건 코드가 고쳐진 뒤에야 의미가 있는 확인이라 오늘 developer 가 먼저 고치고, 다음 디자이너 작업 때 눈으로 보는 확인을 이어가도록 순서를 정리했다.
