# Day 10 — designer

## 오늘 한 것
PM 목표대로 어제(10-17) brand-feature-developer 가 추가한 `.done-story-label`("당신의 스트릿")을
실제로 렌더링해서 확인했다.

- `app/index.html`, `app/styles.css`, `app/app.js` 를 읽고 `showComplete()`(app.js)가 만드는
  완료 카드(`.done-card`) 구조를 전부 정리했다: `.modal-kicker`("REQUEST COMPLETE" + 점, 오렌지)
  → 접수됨 제목 → "접수번호" 라벨(`.modal-sub`, muted-foreground) → 접수번호(`.receipt`, 색 없음,
  36px) → 안내 문구 → (있으면) "당신의 스트릿" 라벨(`.done-story-label`) → 한 줄 이야기 인용구
  (`.done-story`). 이어서 뒷면 목업 카드, 결제 안내 카드(`.pay-card`, `.pay-amount` 가 오렌지)가
  별도 카드로 붙는다 — 모두 `COMPONENTS.md` 에 적힌 대로 `.card.wide` 패턴.
- `python3 -m http.server` 로 `app/` 을 띄우고 Playwright(Python, 이미 설치돼 있던 Chromium)로
  실제 `index.html` 을 열었다. app.js 는 모듈 스코프라 콘솔에서 `showComplete()` 를 직접 부를 수
  없어서, 같은 클래스·마크업을 그대로 복제한 테스트 전용 스크립트(`/tmp/inject_complete.js`,
  저장소에는 없음)를 페이지에 주입해 `#chatLog` 에 완료 카드 + 목업 카드 + 결제 카드를 실제
  `styles.css` 로 렌더링했다. 접수번호는 "OS-TEST", 결제 링크는 `href="#"` 로 막은 가짜 값만
  썼다. 실제 네트워크 요청(로그인, Apps Script 호출)은 전혀 보내지 않았다.
- 데스크톱(1280px)과 모바일(375px) 폭에서 스크린샷을 찍었고, 모바일 폭에는 50자가 넘는 긴 한 줄
  이야기도 넣어 테스트했다.

### 확인한 사실
- **오렌지가 같은 카드 안에서 2곳(수정 전) 겹쳤다.** `.done-card` 는 이미 `box-shadow` 를
  `--accent` 로 써서 "가장 중요한 카드"를 표시하는데, 카드 안에도 `.modal-kicker`("REQUEST
  COMPLETE" + 점)가 오렌지 글자색을 쓰고 있었다. 여기에 `.done-story-label` 이 오렌지 글자색을
  추가로 쓰면서, 같은 카드 안에서 오렌지 텍스트가 두 군데(+그림자까지 세 군데)가 되어
  `COMPONENTS.md` 의 "카드당 오렌지 1곳" 규칙과 충돌하는 걸 스크린샷으로 직접 확인했다.
  결제 카드(`.pay-amount`)는 별도 카드라 규칙과 충돌하지 않는다.
- **모바일 폭(375px)에서 겹침이나 줄바꿈 깨짐은 없었다.** 50자 넘는 긴 이야기도
  `overflow-wrap: anywhere` 덕에 카드 폭 안에서 자연스럽게 줄바꿈됐고, 라벨과 인용구 사이
  간격(`margin-top`)도 비좁아 보이지 않았다. 즉 신 브랜더가 work_summary 에 남긴 두 걱정 중
  "모바일 겹침"은 실제로는 문제가 아니었고, "오렌지 충돌"은 실제로 맞는 걱정이었다.

## 바뀐 파일
- `app/styles.css` — `.done-story-label` 의 `color` 를 `--accent` → `--muted-foreground` 로 변경.
  크기(11px)·대문자·자간(0.08em)은 그대로 둬서 "색 없이도 라벨로 읽히게" 했고, 바로 위 "접수번호"
  라벨(`.modal-sub`)과 색 톤이 맞춰져 카드 안 라벨들이 일관돼 보인다. 수정 후 다시 스크린샷을 찍어
  카드 안 오렌지가 kicker 1곳(+그림자)으로 줄어든 것을 확인했다.
- `app/COMPONENTS.md` — "카드당 오렌지 1곳" 규칙에 "그림자와는 별개로 카드 내용 색에도 적용된다"는
  설명과, `.done-card` 안에서는 `.modal-kicker` 가 이미 그 1곳이라는 점, `.done-story-label` 이
  왜 `--muted-foreground` 를 쓰는지 근거를 추가.
- `CHANGELOG.md` — v0.6 한 줄 추가.
- `daily/2026-10-18/screen.png`(모바일, 긴 이야기 버전), `daily/2026-10-18/screen_desktop.png`
  (데스크톱) — 수정 후 최종 렌더링 결과.
- `app/config.js`, `app/kakaopay-qr.svg`, `backend/Code.gs` — 건드리지 않음.

## 잘 안 된 것, 아쉬운 것
- app.js 가 모듈 스코프라 `showComplete()` 를 콘솔에서 직접 호출하지 못하고, 같은 마크업을
  수작업으로 복제한 테스트 스크립트를 써야 했다. 복제 과정에서 실수가 있었다면(예: 클래스 하나
  빠뜨림) 실제 화면과 미묘하게 다를 수 있다 — `showComplete()` 본문을 한 줄씩 대조하며 만들어서
  가능성은 낮다고 보지만, developer 가 테스트하기 쉽게 디버그용 전역 노출(`window.__debug` 같은)을
  열어두는 방안을 다음에 검토해볼 만하다.
- 실제 로그인·접수 흐름을 끝까지 타서 완료 화면에 도달하는 "진짜" 경로는 이번에도 시도하지
  않았다(서버 요청 금지 지시에 따름). 그래서 완료 화면 직전 단계(확인 카드 → 접수 버튼 → 완료)
  전환 애니메이션이나 타이밍은 확인 범위 밖이었다.
