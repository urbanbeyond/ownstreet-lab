# Day — brand-feature-developer

## 오늘 한 것
PM 결정(`daily/2026-11-01/pm_decision.md`)에 따라 `docs/naming-rules.md`의 "8. 다음에
할 것" 1·2번을 이어받았다. 코드(`app/`, `backend/`)는 전혀 건드리지 않았다 — 오늘은 설계
문서 작업이고, Stage 2 코드화 트리거 조건(LIVE 시험 주문 확인, 이미지 업로드 방식 결정)은
여전히 미충족이다.

진행 순서:
1. `docs/naming-rules.md` 전체를 다시 읽어 구조를 파악했다. 사전은 별도 데이터 파일이
   아니라 문서 안 마크다운 표(3-1, 3-2절)로 존재한다는 걸 확인하고, 그 구조를 그대로
   따라 추가했다(별도 JSON 파일을 새로 만들지 않음 — 10-29에도, 그리고 8절 "코드화
   시점" 계획에도 "데이터는 코드화할 때 별도 JSON/JS로 분리"라고 되어 있어 지금 단계에서
   분리하는 건 범위 밖이라고 판단).
2. **사전 빈 칸 채우기** (3-1·3-2절): 7절 샘플 시험에서 지목된 "인생"(샘플13), "자신감"
   (샘플19), "노을"(샘플20)을 우선 채웠다. 그 외에 같은 기준(3-1절 "구체적 이미지 단어",
   3-2절 "감정/가치 단어")으로 비슷하게 비어 있을 법한 단어도 추측으로 미리 채웠다 —
   3-1절에 별·달·비·눈·산·나무·돌·강(자연물), 3-2절에 열정·꿈·성장·균형·경계·소속(추상
   가치어). 각 단어에 한국어 치환 후보 2개, 영어 치환 후보 3개를 기존 표와 같은 형식으로
   붙였다. 추가한 이유와 추측이라는 한계를 표 바로 아래 인용문으로 남겼다.
3. **포함 관계 매칭 구체화** (새 8절): 7-2절에서 "제안으로만" 남겼던 것을 실제로 코드화
   가능한 수준까지 끌어올렸다.
   - 매칭 순서 의사코드: 정확 일치 → 예외 토큰 확인 → 포함 관계(긴 표제어 우선 비교,
     토큰의 맨 앞/맨 뒤에 붙어 있을 때만 인정, 나머지 글자가 1개뿐이면 추가로 조각
     예외 확인) → 없으면 사전 밖으로 처리.
   - 오매칭 방지 예외 목록 두 종류를 표로 작성: (A) 토큰 전체를 예외 처리(불안·불편·
     불가능·바다표범·걸음걸이·길이·다름없이·새벽잠 — 각각 왜 예외인지 이유를 적음),
     (B) 표제어를 뺀 나머지가 1글자일 때 쓰는 "조각 예외"(안·편·이·상).
   - 이 매칭을 어디에 적용하고 어디에 적용하지 않는지(축1에는 적용 안 함, 2글자 이하
     토큰에는 적용 안 함)와, 사용자에게 보여줄 설명 문구에서 숨기지 않는다는 원칙도
     같이 적었다.
   - 7-2절에는 "구체화한 내용은 8절에 있다"는 참조를 추가했다.
4. 절 번호가 뒤섞여서(새 절을 7절과 8절 사이에 끼워 넣었다가) 기존 8절("다음에 할 것")과
   충돌해, 전체를 다시 정리했다 — 새로 쓴 절을 8절로, 기존 "다음에 할 것"을 9절로 밀고
   본문 안의 교차 참조(여러 곳에 있던 "7절/8절/9절 참고" 같은 문구)를 전부 실제 번호에
   맞게 다시 고쳤다. (`grep`으로 전체 절 번호를 다시 훑어 누락 없이 확인)
5. 9절("다음에 할 것")을 오늘 한 일에 맞게 갱신했다 — 처리한 두 항목은 줄긋기(~~)로
   표시하고 "11-01에 진행했다. 다만 여전히 추측 기반"이라고 남겼고, 손대지 않은 항목
   ("키워드 없음" 대응, 상표 유사 필터)은 그대로 두되 "오늘 범위 밖"을 명시했다. 오늘
   새로 발견한 다음 과제도 하나 추가했다 — 오늘 채운 새 단어들(노을·별·경계·성장 등)
   에 대한 포함 관계 예외 목록은 아직 점검하지 못했다는 것.
6. 문서 맨 위에 "갱신: 2026-11-01" 줄을 추가해 오늘 바뀐 부분을 한눈에 알 수 있게 했다.

## 잘 안 된 것, 아쉬운 것
- **사전 확장은 여전히 추측이다.** 오늘 채운 17개 단어(노을·별·달·비·눈·산·나무·돌·강·
  인생·자신감·열정·꿈·성장·균형·경계·소속) 중 실제 손님 입력에서 나온 건 하나도 없다.
  7절 샘플에서 지목된 3개("인생", "자신감", "노을")만 실제 시험에서 드러난 수요고,
  나머지 14개는 "같은 종류니까 비슷하게 비어 있을 것"이라는 유추일 뿐이다. 실제 손님
  답변이 쌓이면 이 중 상당수가 안 쓰일 수도 있고, 지금 안 채운 훨씬 중요한 단어가
  있을 수도 있다.
- **포함 관계 매칭의 예외 목록도 똑같이 추측이다.** 8-3절의 모든 예외("불안", "바다
  표범" 등)는 "있을 법한 오매칭"을 내가 상상해서 적은 것이지, 실제로 그런 토큰이
  입력된 걸 본 게 아니다. 오히려 실제로는 전혀 다른 오매칭이 나올 가능성이 더 크다고
  본다. 이 설계가 "완벽한 언어 분석"이 아니라 "어느 정도 걸러내는 안전장치"라는 점을
  8-5절에 분명히 적었다.
- 오늘 새로 추가한 3-1·3-2절 단어들에 대해 포함 관계 오매칭 가능성을 점검할 시간이
  부족했다(예: "경계"와 "경계심", "성장"과 "성장통"처럼 비슷한 패턴이 또 있을 수
  있다). 9절에 다음 과제로 남겼다.
- 작업 중 절 번호가 한 번 어긋나서(8절 자리에 새 절을 넣으려다 기존 "다음에 할 것"과
  충돌) 전체 문서의 교차 참조를 다시 훑어 고쳐야 했다. 결과적으로는 바로잡았지만, 이런
  문서 구조 작업은 번호를 먼저 전부 정하고 쓰는 게 더 안전했을 것 같다.
