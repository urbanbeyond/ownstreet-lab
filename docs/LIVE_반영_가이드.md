## 1. 왜 서버부터 바꿔야 하나

"서버"는 손님 주문을 받아 구글 스프레드시트에 적고 접수번호(OS-…)를 내주는 프로그램이다. 주문 스프레드시트에 붙어 있는 **Apps Script** 가 그것이고, 소설에서는 "창고"라고 부른다.

| | 지금 실제 서비스 (1버전) | 새 버전 (2버전) |
|---|---|---|
| 받을 수 있는 항목 | 이름, 전화번호, 이미지 링크 | 위의 것 + **사이즈, 주소, 배송 요청, 한 줄 이야기** |
| 만든 사람 | 처음 서비스를 열 때 | 윤 개발자 (`backend/Code.gs`) |
| 지금 상태 (10-24 점검) | 응답에 버전 표시 없음 = 1버전 | LAB 서버는 이미 2버전 (의장 처리, 2026-10-08 기록) |

새 채팅 화면은 사이즈·주소·한 줄 이야기까지 보낸다. 1버전 서버 그대로 화면만 바꾸면 손님이 주문 끝에서 **"지금은 주문을 준비하고 있습니다"** 를 보고 멈춘다. 그래서 순서는 **서버 먼저, 화면 다음**이다.

2버전 서버는 지금의 옛 한 페이지 화면 주문도 그대로 받는다. 그래서 서버를 먼저 바꿔도 손님에게는 영향이 없다.

## 3. 서버를 2버전으로 올리기 (의장이 직접, 6단계)

**붙여 넣을 코드**: 아래 주소를 브라우저에서 열고 전체 선택(Ctrl+A) → 복사(Ctrl+C).
https://raw.githubusercontent.com/urbanbeyond/ownstreet-lab/main/backend/Code.gs
맨 윗부분에 `OWN STREET — 접수 서버 v2` 가 보이면 맞는 코드다 (489줄).

1. **`ownstreetdb` 를 열고 확장 프로그램 → Apps Script** 로 들어간다. (LAB 시트 `ownstreet-lab` 이 아니다)
2. **붙여 넣기 전에** 지금 코드 위쪽의 `const SPREADSHEET_ID = '…'` 줄을 본다.
   - 따옴표 안이 **비어 있으면** → 그대로 3번으로.
   - **긴 글자가 있으면** → 그 글자를 복사해 두고, 왼쪽 **⚙ 프로젝트 설정 → 맨 아래 스크립트 속성 → 스크립트 속성 추가** → 속성 `SPREADSHEET_ID` / 값: 복사한 글자 → **저장**.
   - 이 단계를 건너뛰면 새 코드가 주문 시트를 못 찾는다. 이 글자는 GitHub·AI 팀과의 대화 어디에도 붙여 넣지 않는다 (저장소가 공개다).
   - 이미 있는 다른 속성(예: `OS_LAST_SEQ`)은 그대로 둔다.
3. **지금 코드 전체를 복사해서 메모장에 붙여 둔다.** 되돌리기용이다.
4. 편집기의 코드를 **모두 지우고** 새 코드를 붙여 넣은 뒤 **저장**(💾 또는 Ctrl+S).
5. 위쪽 함수 선택 칸에서 **`setup`** 을 고르고 **▶ 실행**. 권한 창이 뜨면 허용한다.
   - 실행 로그에 **✅ 로 시작하는 줄이 3개**(스프레드시트 연결 / 머리글 13칸 / Firebase API 키) 나오면 정상.
   - ❌ 가 나오면 그 줄을 캡처해서 보낸다 (아래 5번 "문제가 생겼을 때").
6. 오른쪽 위 **배포 → 배포 관리 → 연필(✏️) 아이콘 → 버전: "새 버전" → 배포.**
   - **"새 배포"를 만들지 않는다.** 서버 주소(`…/exec`)가 바뀌어 실제 서비스 화면이 서버를 못 찾게 된다.

## 4. 제대로 올라갔는지 확인

- **서버 상태**: 아래 주소를 브라우저 주소창에 열면 한 줄 글자가 나온다 (고객 데이터는 나오지 않는다).
  https://script.google.com/macros/s/AKfycbxmtj6Pi5mBlwZSBJdD5247W6U5aOU_-sHmoalYTQQT6dVNzW80seV7m2NvHo0OSkgM_Q/exec
  **정상: `"version":2` 와 `"ready":true` 와 `"storage":true`** 가 모두 보인다.
- **시트 머리글**: `ownstreetdb` 의 `REQUESTS` 탭 **첫 줄만** 본다 (고객 줄은 열어 볼 필요 없다).
  `접수번호 | 접수시간 | 이메일 | 이름 | 전화번호 | URL | 상태 | 사이즈 | 주소 | 배송 요청 | 한 줄 이야기 | clientRef | 동의 시각` — 앞 7칸은 예전 그대로, 새 6칸이 "상태" 뒤에 붙는다.
- 확인이 끝나면 AI 팀(Claude)에게 **"서버 올렸어"** 라고만 보낸다. 운영이 서버 점검(Server Check)으로 version 2 를 한 번 더 확인한다.

## 5. 문제가 생겼을 때

| 보인 것 | 원인 | 할 일 |
|---|---|---|
| 서버 주소에 `version` 이 없음 | 6단계에서 "새 버전"을 안 눌렀거나, 새 배포를 만들었음 | 배포 관리 → 연필 → 새 버전 → 배포 를 다시 |
| `"storage":false` | 2단계의 `SPREADSHEET_ID` 값이 틀림 | 스크립트 속성 값 다시 확인 |
| `"ready":false` + `FIREBASE_API_KEY` 얘기 | 코드 맨 위 `FIREBASE_API_KEY` 줄이 비었음 | 새 코드를 다시 통째로 붙여 넣기 |
| setup 에서 **"머리글 충돌"** | `REQUESTS` 탭의 H 열 이후에 의장이 따로 써 둔 칸이 있음 (덮어쓰지 않고 멈춘 것) | 그 칸을 옮기거나 AI 팀에게 알려 주기 |
| 주문이 `SERVER_ERROR` 로 막힘 | 2단계를 건너뛰어 시트를 못 찾음 (가짜 성공은 나오지 않는다) | 2단계 다시 |

**되돌리기**: 배포 → 배포 관리 → 연필 → 버전에서 **이전 버전**을 골라 배포한다. 또는 메모장에 둔 옛 코드를 다시 붙여 넣고 새 버전으로 올린다. 새로 생긴 머리글 칸은 시트에 남지만 옛 코드는 그 칸을 신경 쓰지 않아 해가 없다.

## 6. 그다음 — 실제 서비스(ownstreet.life)에 새 화면 올리기

서버 확인이 끝나면 운영(Claude)이 바로 진행한다. 의장이 직접 누를 수도 있다.
- GitHub → Actions → **Promote LAB to LIVE** → Run workflow → 확인 칸에 **`LIVE`** 입력 → 실행.
- 올라가는 것: LAB 배너·결제 차단·미리보기 표시가 **빠진** 원래 화면. 실제 결제 안내와 실제 서버 주소가 들어 있다.
- 안전장치: 화면 안에 LAB 서버 주소나 LAB 배너가 섞여 있으면 반영이 스스로 멈춘다.

**새 화면에 들어가는 것 (지금 LAB 기준)**
- 대화형 채팅 주문: 이미지 링크 → 한 줄 이야기(건너뛰기 가능) → 사이즈 → Google 로그인 → **신청자명(입금자명)** → 연락처 → 주소 → 배송 요청 → 확인 → 접수
- 질문은 박스 없이 글자만, 네모 박스는 답(입력칸·손님이 보낸 답)에만 (R-015)
- 이름 대신 **신청자명(입금자명)**, 받는 분이 다르면 배송 요청에 적도록 안내 (R-016)
- 진행 막대, 티셔츠 뒷면 목업, "당신의 스트릿" 라벨, 이어하기(탭을 닫았다 열어도 이어서), 인앱 브라우저 안내

**반영 후 확인**
1. 폰으로 ownstreet.life 를 열어 새 채팅 화면이 뜨는지 본다 (LAB 배너가 없어야 정상).
2. **시험 주문 1건**을 끝까지 넣는다 — 새 채팅 화면의 주문이 실제 서비스 서버에 들어가는 것은 이번이 처음이다.
   - 이름·전화번호는 지어낸 값을 쓴다. 배송 요청에 "테스트 주문" 이라고 적는다. 접수번호(OS-…)가 뜨는지, `REQUESTS` 에 사이즈·주소·한 줄 이야기 칸이 채워지는지 본다.
   - 확인한 뒤 그 줄의 "상태"를 테스트로 표시해 둔다 (제작·결제로 넘어가지 않게).
3. 이상이 있으면 화면에 뜬 문구와 어느 질문 단계였는지를 알려 준다. 급하면 LIVE 를 이전 상태로 되돌릴 수 있다 (Netlify 의 이전 배포로).

## 7. 다른 방법 (참고)

| 방법 | 내용 | 언제 |
|---|---|---|
| A. 의장이 직접 (이 문서 3번) | 6단계를 직접. 막히면 화면 캡처를 보내면 운영이 짚어 준다 | 지금 권장 |
| B. 운영이 의장 컴퓨터 브라우저로 대신 | Claude 데스크톱 앱이 켜진 PC 에서 이 대화를 열어 컴퓨터를 연결하면, 운영이 Apps Script 편집기(script.google.com)로 바로 들어가 진행. Google 로그인·권한 허용은 의장이 직접 누른다. 스프레드시트 데이터는 열지 않는다 | PC 와 데스크톱 앱이 있을 때 |
| C. "서버 배포 버튼" 만들기 | 의장 PC 에서 Google 연결을 한 번 해 두면, 다음부터 GitHub 버튼 하나로 서버 교체·배포 | 서버를 자주 고치게 되면 |
| D. 오늘은 하지 않기 | ownstreet.life 는 지금 옛 한 페이지 화면으로 정상 동작 중. 서버 작업을 할 수 있을 때 해도 손님에게 문제없음 | 시간이 없을 때 |

**안 되는 방법**: 서버는 그대로 두고 화면만 올리기. 새 화면은 서버가 2버전인지 먼저 확인하고, 아니면 "지금은 주문을 준비하고 있습니다"에서 멈춘다. 옛 서버가 사이즈·주소를 모르고 버린 채 접수번호만 주는 사고를 막으려고 윤 개발자가 일부러 그렇게 만들었다. 그래서 화면만 올리면 실제 손님 주문이 전부 막힌다.
