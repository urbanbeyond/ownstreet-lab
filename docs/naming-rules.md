# OWN STREET 네이밍 규칙 설계 (브랜드명 후보 생성)

작성: 신 브랜더 (brand-feature-developer) · 2026-10-29
목적: ROADMAP Stage 2 "취향 한 줄 → 브랜드명 후보" 기능을 위한 **규칙·사전 기반** 설계.
서버 없이 브라우저 안에서 동작하는 것을 전제로 한다(선언문 "AI 도구 상관없이 문을 낮춘다" +
현재 Stage 2 가 코드 착수 전이라 외부 AI API 연결은 하지 않는다).

이 문서는 **설계안**이다. 아직 코드로 옮기지 않았다. 10-26 회의 결정대로 Stage 2 트리거 조건
(① LIVE 시험 주문, ② 상태 플래그 전수조사 — 완료, ③ 이미지 업로드 방식 결정)이 모두 충족된
뒤, 그리고 실제 손님의 story 답변이 쌓인 뒤 이 규칙을 다시 맞춰보고 코드화한다.

---

## 0. 전제와 한계 — 먼저 밝혀둔다

- **실제 손님의 story 답변은 아직 하나도 없다.** `docs/chat-script.md`(10-17)를 쓸 때도 같은
  문제가 있었고, 10-26 회의에서도 신 브랜더 본인이 이 점을 가장 먼저 짚었다. OPERATOR_TODO 에
  관찰 가능 여부를 질의했으나 오늘까지 답이 없다(PM 결정문에도 "보류"로 명시).
- 그래서 이번 문서는 **본인이 직접 다양한 길이·어투의 샘플 문장 20개를 만들어 규칙을 시험**하는
  방식으로 대신한다(10-26 회의에서 본인이 제안한 대안). 아래 "5. 샘플 문장으로 시험"이 그 결과다.
  **이 샘플은 추측이다.** 실제 손님 답변이 쌓이면 이 문서의 사전·규칙은 다시 맞춰야 한다 — 특히
  "한국어 조사·종결어미를 얼마나 거칠게 잘라내도 되는지"는 실제 문장을 봐야 확신할 수 있다.
- 이 기능은 **AI 가 대신 정해주고 끝나는 게 아니다.** 선언문 기준대로, 후보는 항상 "다시 뽑기"와
  "내가 직접 쓰기"를 함께 둔다(아래 6번). 규칙·사전이 만드는 건 **출발점**이고, 마지막 선택은
  손님이 한다.

## 1. 전체 흐름

```
입력: story (손님이 쓴 한 줄, 1~200자. 비어 있을 수 있음 — 건너뛰기 가능 질문)
  ↓ 1단계: 키워드 추출 (조사·종결어미 제거, 핵심 단어 1~3개 뽑기)
  ↓ 2단계: 단어 치환 (일상어 → 브랜드스러운 단어, 사전 매핑)
  ↓ 3단계: 세 가지 축으로 각각 조합 (직설적 / 은유적 / 영어조합)
  ↓ 4단계: 접두어·접미어 사전과 결합해 각 축마다 1~2개, 총 3개 이상 후보 생성
출력: 브랜드명 후보 목록(서로 다른 방향 3개 이상) + 왜 그 이름인지 한 줄 설명
      + "내가 직접 쓰기" 입력창 + "다시 뽑기" 버튼 (항상 함께)
```

story 가 비어 있으면(건너뛴 손님) 네이밍 단계 자체를 건너뛰거나, 키워드 없이 접두어/접미어
사전만으로 "일반 후보"를 보여주는 두 가지 길이 있다 — 이건 화면 설계(디자이너 몫)와 맞물려
있어 이 문서에서는 선택지로만 남긴다.

## 2. 1단계 — story 에서 키워드 뽑기

### 2-1. 전처리
- 양끝 공백 제거, 마침표·물결·이모지 제거(이모지는 브랜드명에 쓰지 않는다 — 인쇄물에 올라갈
  이름이라 특수문자 없는 쪽이 안전).
- 문장을 공백 기준으로 토큰 분리.

### 2-2. 조사·종결어미 제거 (규칙 기반, 형태소 분석기 없이)
외부 라이브러리 없이 브라우저 안에서 돌아가야 하므로, **흔한 조사·어미를 꼬리에서부터 긴 것부터
매칭해 잘라내는 방식**을 쓴다(정교한 형태소 분석은 아니지만 짧은 한 줄 문장에는 충분히 작동).

```js
// 긴 꼬리부터 먼저 시도 (짧은 조사가 긴 조사 안에 포함되는 경우가 있어 순서가 중요하다)
const TAIL_PATTERNS = [
  '이라는', '이었던', '하는', '했던', '한다', '했다', '이다', '였다',
  '에게', '에서', '으로', '로써', '처럼', '같이', '만큼',
  '이고', '이며', '이지만', '하고', '하지만',
  '은', '는', '이', '가', '을', '를', '에', '의', '와', '과', '도', '만',
];
```
- 토큰 끝에서 패턴을 매칭되는 즉시 잘라낸다. 두 글자 이하 토큰은 자르지 않는다(과하게 잘려
  의미 없는 글자만 남는 것 방지. 예: "색"은 그대로 둔다).
- 동사/형용사형 토큰("만들었어요", "좋아해요" 등)은 명사가 아니라서 브랜드명 재료로 쓰기
  어렵다 — 이런 토큰은 **키워드 후보에서 제외**하고, 명사형 토큰만 남긴다. 판별은 완벽할 수
  없으니 "흔한 동사 종결 패턴 목록"(`~어요`, `~았다`, `~한다` 등으로 끝나는 토큰)으로 거른다.

### 2-3. 핵심 단어 선정
- 남은 토큰 중 2글자 이상인 것을 핵심 단어 후보로 삼는다.
- 우선순위: ① 색/계절/동물/자연물처럼 **구체적 이미지 단어**(아래 사전에 있는 단어) > ② 감정/
  가치 단어("자유", "용기" 등) > ③ 그 외 명사.
- 핵심 단어 1~3개를 남긴다. 토큰이 하나뿐이면 그거 하나만 쓴다.
- 영어 단어가 섞여 있으면(예: "나의 street") 그대로 핵심 단어 후보에 포함한다 — 영어조합 축에서
  바로 쓸 수 있다.

## 3. 2단계 — 손님 단어 치환 사전

손님이 쓴 일상어를 그대로 쓰면 밋밋하거나, 반대로 브랜드명으로 쓰기엔 너무 평범한 경우가 많다.
**치환은 "다른 단어로 바꿔치기"가 아니라 "같은 단어의 더 선명한 버전을 보여주는 것"**이어야
한다 — 손님이 쓴 단어가 사라지면 "내 이야기가 담긴다"는 선언문 기준을 어기게 된다. 그래서 치환
결과에는 항상 **원래 단어도 함께 보여준다** (예: 후보 설명에 "너의 '색'에서").

### 3-1. 색/계절/자연 치환 (구체 이미지 단어 사전, 예시)

| 손님 단어 | 치환/확장 후보 (한국어) | 치환/확장 후보 (영어) |
|---|---|---|
| 색 | 빛깔, 물결 | HUE, TONE, SHADE |
| 하늘 | 창공, 구름 | SKY, CLOUD, ATMO |
| 밤 | 야행, 심야 | NIGHT, MIDNIGHT, NOIR |
| 새벽 | 여명, 첫빛 | DAWN, FIRST LIGHT |
| 바다 | 파도, 수평선 | WAVE, TIDE, HORIZON |
| 길 | 스트릿, 여정 | STREET, ROUTE, WAY |
| 걸음 | 발자국, 보폭 | STEP, STRIDE, PACE |
| 불 | 불씨, 화염 | FLAME, EMBER, SPARK |
| 바람 | 숨결, 흐름 | WIND, BREEZE, FLOW |
| 꽃 | 개화, 봉오리 | BLOOM, BUD, PETAL |

### 3-2. 감정/가치 치환 (추상 단어 사전, 예시)

| 손님 단어 | 치환/확장 후보 (한국어) | 치환/확장 후보 (영어) |
|---|---|---|
| 자유 | 해방, 날개 | FREE, WING, LOOSE |
| 용기 | 결심, 담대함 | BOLD, DARE, NERVE |
| 평온 | 고요, 잔잔함 | CALM, STILL, QUIET |
| 반항 | 균열, 어긋남 | RIOT, CRACK, OFF |
| 처음 | 시작, 출발선 | FIRST, ORIGIN, DAY ONE |
| 혼자 | 홀로, 단독 | SOLO, ALONE, LONE |
| 다름 | 개별, 고유함 | DIFFER, ONLY, UNIK |

**사전은 완성본이 아니다.** 실제 손님 답변이 쌓이면 가장 자주 나오는 단어 중심으로 사전을
다시 짠다(아래 7번 "다음에 할 것" 참고). 지금은 placeholder("처음으로 내가 정한 나의 색")와
흔히 쓰일 법한 감성 단어들을 중심으로 먼저 채웠다.

### 3-3. 치환 원칙
- 치환은 **선택사항**이다 — 원래 단어 그대로 쓰는 후보도 항상 하나는 포함한다(직설적 축이
  이 역할을 한다. 아래 4번).
- 사전에 없는 단어는 치환하지 않고 그대로 쓴다. 억지로 끼워 맞추지 않는다 — 차라리 접두어/
  접미어만으로 꾸민다.
- 치환 후보는 사전마다 2~3개로 제한한다. 너무 많으면 "어느 걸 골라야 할지 모르는" 선택 피로가
  생긴다.

## 4. 3단계 — 방향을 가르는 세 가지 축

같은 재료(키워드)로 **서로 다른 세 방향**을 만든다. "서로 다른 방향 3개 이상"(PM 역할 설명)의
실체가 이 축이다. 세 축은 "같은 단어를 얼마나 가깝게/멀게 다루는가"의 차이다.

### 축 1 — 직설적 (Literal)
손님이 쓴 단어를 **거의 그대로**, 치환 없이 쓴다. 접두어/접미어로 브랜드 느낌만 더한다.
가장 "내 이야기가 담겼다"는 확신이 드는 축 — 가장 안전하고, 가장 보수적이다.

- 규칙: `[핵심 단어]` + `[접미어 사전 중 하나]` 또는 `[접두어 사전 중 하나]` + `[핵심 단어]`
- 예시 (핵심 단어: "색"): `색 스트릿`, `마이 색`, `색 하우스`
- 예시 (핵심 단어: "새벽"): `새벽 하나`, `디어 새벽`, `새벽 공방`

### 축 2 — 은유적 (Metaphor)
핵심 단어를 **치환 사전(3-1, 3-2)**으로 바꾸거나 확장해서, 손님이 쓴 단어가 바로 보이지는
않지만 뜻은 이어지게 만든다. 손님 단어는 후보 설명("너의 '색'에서 번져 나온 이름")에서
밝혀준다 — 숨기는 게 아니라 "한 걸음 번역"하는 것.

- 규칙: `[치환 단어]` + `[접미어]` 또는 `[접두어]` + `[치환 단어]`, 혹은 두 치환 단어를 조합
- 예시 (핵심 단어: "색" → 치환 "빛깔"): `빛깔 하나`, `첫 빛깔`
- 예시 (핵심 단어: "자유" → 치환 "날개"): `날갯짓`, `무명의 날개`
- 예시 (핵심 단어: "새벽" → 치환 "여명"): `여명 공방`, `여명과 걸음` (두 치환어 조합: "여명" +
  "걸음"의 치환어 "보폭"을 섞지 않고, 2단계에서 뽑은 두 번째 키워드가 있으면 그것과 조합)

### 축 3 — 영어조합 (English Mix)
핵심 단어(또는 치환 단어)의 **영어 버전**을 접두어/접미어 사전의 영어 단어와 조합한다. 스트릿
웨어 브랜드 이름에 흔한 패턴(짧은 영단어 2개 붙이기, 대문자, `.`이나 `_` 같은 기호 하나 섞기)을
따른다. 다만 기존 실존 브랜드명을 베끼지 않도록 **고유명사가 아닌 일반 단어 조합**만 쓴다.

- 규칙: `[영어 치환 단어]` + `[영어 접미어]` 또는 `[영어 접두어]` + `[영어 치환 단어]`
- 예시 (핵심 단어: "색" → "HUE"): `HUE WORKS`, `OWN HUE`, `HUE.CO`
- 예시 (핵심 단어: "자유" → "FREE"): `FREE LINE`, `FREE STUDIO`, `DAY ONE FREE`
- 예시 (핵심 단어: "새벽" → "DAWN"): `DAWN WORKS`, `DAWN.CO`, `MY DAWN`

## 5. 접두어/접미어 사전

세 축 모두에서 재사용하는 "브랜드 느낌을 더하는 조각"이다. **스트릿웨어 분위기 + 선언문의
"자기만의 것" 정신**을 기준으로 골랐다. 실존 브랜드 접미어(예: 특정 유명 브랜드의 시그니처
접미어)를 베끼지 않도록, 흔하게 쓰이는 범용 단어 중심으로만 담았다.

### 5-1. 한국어 접두어 (핵심 단어 앞에 붙임)
| 접두어 | 느낌 |
|---|---|
| 마이 | 소유·개인화 ("마이 색") |
| 디어 | 다정하게 부르는 말 ("디어 새벽") |
| 무명의 | 익명·겸손 ("무명의 날개") |
| 첫 | 시작·처음 ("첫 빛깔") |
| 홀로 | 혼자·독립 ("홀로 걸음") |

### 5-2. 한국어 접미어 (핵심 단어 뒤에 붙임)
| 접미어 | 느낌 |
|---|---|
| 하나 | 단수·고유함 ("색 하나") |
| 공방 | 만드는 곳, 수공업 느낌 ("새벽 공방") |
| 상회 | 가게·상점의 옛말, 스트릿 브랜드에 흔한 레트로 느낌 ("길 상회") |
| 과 걸음 | 동행·여정 ("바람과 걸음") |
| 하우스 | 모임·거점 ("색 하우스") |

### 5-3. 영어 접두어
| 접두어 | 느낌 |
|---|---|
| OWN | 선언문·서비스명과 직결 ("OWN HUE") |
| DAY ONE | 처음·시작 ("DAY ONE FREE") |
| MY | 소유·개인화 ("MY DAWN") |
| NO NAME | 익명·반권위 ("NO NAME WAVE") |

### 5-4. 영어 접미어
| 접미어 | 느낌 |
|---|---|
| WORKS | 제작·공방 느낌, 스트릿웨어에 흔함 |
| STUDIO | 작업실, 브랜드 느낌 |
| CO | "Company"의 줄임, 레트로 로고 느낌 |
| LINE | 계열·라인업 느낌 |
| CLUB | 소속감, 스트릿웨어에 흔함 |

> **주의**: `WORKS`, `STUDIO`, `CO`, `CLUB` 같은 영어 접미어는 스트릿웨어 업계에서 매우 널리
> 쓰이는 범용 단어다(특정 브랜드의 고유 표현이 아님). 다만 최종 후보를 화면에 내보내기 전,
> 코드화 단계에서 "실존 상표와 똑같은 전체 조합"이 나오지 않는지 가벼운 금지 단어 필터를
> 하나 두는 것을 제안한다(6-3 참고) — 완벽한 상표 검색은 아니지만 최소한의 안전장치는 둔다.

## 6. 손님의 선택권 — 항상 함께 두는 것

선언문 "AI 는 도구다. 추천은 출발점일 뿐이고, 마지막 선택은 사용자가 한다"를 그대로 기능으로
옮기면:

1. **후보 3개 이상은 항상 서로 다른 축에서 최소 하나씩 나온다.** 세 개 다 같은 축이면 "다른
   방향"이 아니라 "같은 방향의 변주"가 된다.
2. **"다시 뽑기" 버튼** — 같은 story 로 다른 조합을 다시 보여준다(사전 안에서 다른 치환 단어·
   접두어/접미어를 골라 재조합).
3. **"내가 직접 쓰기" 입력창은 후보 목록과 항상 같은 화면에, 후보들과 동등한 위치에 둔다.**
   후보 아래 작게 붙는 "기타" 취급이 아니라, 선택지 중 하나로 보이게 한다 — "추천은 출발점"
   이라는 원칙이 화면에서도 보이도록.
4. 후보를 고른 뒤에도 **글자를 고칠 수 있어야 한다**(완전히 새로 쓰는 게 아니라 후보를 바탕으로
   다듬는 중간 단계). 이건 화면/상태 설계가 필요해 이 문서 범위 밖이지만 원칙으로 남긴다.

### 7-1. 시험에서 드러난 문제 — "키워드 없음" 케이스 (20개 중 3개, 15%)
샘플 3·8·15 ("그냥 좋아서요", "ㅎㅎ 그냥 멋있어서 샀어요", "그냥 생각나서")처럼 **명사형
키워드가 없는 짧은 구어체 문장**이 생각보다 자주 나올 수 있다. 이 경우 네이밍 자체가 막힌다.
대응안 두 가지를 제안한다(코드화 단계에서 결정):
- (a) 접두어/접미어 사전만으로 "일반 후보"를 보여준다 (예: `OWN HUE`, `DAY ONE`처럼 서비스
  정체성 쪽 단어를 핵심 단어로 대신 쓴다).
- (b) "조금 더 적어주면 더 잘 맞는 이름을 만들 수 있어요"처럼 **다시 물어보는 재질문**을 한
  번 제안한다. 다만 손님이 이미 "건너뛰기"를 선택할 수 있는 질문이라, 강요처럼 느껴지지
  않게 "괜찮아요, 건너뛸 수도 있어요"를 항상 같이 둔다.
- 개인 의견: (b)가 선언문 기준(AI가 대신 정하지 않고 손님 생각이 담기게)에 더 맞는다고 본다.
  다만 두 번 묻는 건 대화 흐름을 늘리는 일이라, 디자이너·PM 과 같이 판단할 사안으로 남긴다.

### 7-2. 시험에서 드러난 문제 — 사전 표제어와 실제 입력의 불일치
샘플 11("불꽃")이 사전 표제어("불")와 정확히 일치하지 않아 치환이 안 되는 문제가 나왔다.
**부분 일치(포함 관계) 매칭**을 추가하는 것을 제안한다 — 예: 토큰에 사전 표제어가 **포함**
되어 있으면(앞뒤에 다른 글자가 붙어 있어도) 그 표제어의 치환 규칙을 적용. "불꽃"은 "불"을
포함하므로 "불"의 치환 규칙("불씨, 화염 / FLAME, EMBER, SPARK")을 그대로 쓸 수 있다. 다만
이 방식은 오매칭 위험도 있다("불안"에 "불"이 포함되지만 뜻이 다르다) — 코드화 단계에서
"포함되지만 뜻이 다른 예외 목록"을 같이 관리해야 한다.

### 7-3. 축별 체감 — 어느 축이 가장 안정적이었나
- **축1(직설적)**: 20개 중 "키워드 없음" 3개를 빼면 17개 전부 자연스럽게 작동했다. 가장
  안정적이고, 사전 의존도가 가장 낮다(접두어/접미어만 있으면 됨).
- **축2(은유적)**: 핵심 단어가 치환 사전에 없으면(샘플 13, 20) 품질이 눈에 띄게 떨어진다
  (치환 없이 그대로 쓰거나, 아예 생략해야 함). 사전 범위를 넓히는 게 가장 중요한 다음 과제.
- **축3(영어조합)**: 영어 사전이 가장 좁아서(한국어 사전보다 단어 수가 적음) 치환 실패 시
  "직역"(샘플 13, 20처럼 "MY LIFE", "MY SUNSET")으로 떨어지는데, 직역도 나쁘지 않게
  들리는 경우가 의외로 많았다(영어는 직역해도 "브랜드명 같은 느낌"이 어느 정도 유지됨).
  한국어 축2보다 사전 부족의 티가 덜 난다.
