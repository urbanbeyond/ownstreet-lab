# OWN STREET 대화 대본

작성: 신 브랜더 (brand-feature-developer) · 2026-10-17
목적: 채팅형 주문(2026-10-15 developer 이식, 2026-10-16 designer 다듬음)의 질문 순서에 맞춰
각 단계 안내 문구를 다듬고, 특히 "한 줄 이야기" 질문이 선언문(`OWN_STREET_LIFE.md`)에 맞게
"손님의 생각을 묻는 자리"로 작동하는지 확인한다. 이 문서는 대본이고, 실제 구현은
`app/app.js` 의 `QUESTIONS`, `greet()`, `askLogin()`, `showConfirm()`, `showComplete()` 에 있다.

## 기준 — 선언문에서 가져온 것
- "AI가 대신 정해주고 끝나는 기능이 아니라, 사용자의 생각과 취향이 결과물에 담기게 한다."
- "결과물이 얼마나 멋진지보다, 그 과정에서 사용자가 자기다움을 발견하는지가 더 중요하다."
- 선언문 본문: "내 가치관과 수많은 생각이 버무려진 스토리, 내 이야기가 담겼다면 그걸로 의미는 충분하다."

이 기준에서 보면 "한 줄 이야기" 질문은 이번 채팅 대본에서 **유일하게 정답이 없는 질문**이다.
이미지 링크·사이즈·이름·전화번호·주소·배송 요청은 모두 "정확한 정보"를 받는 질문이고,
한 줄 이야기만 "손님의 생각"을 받는 질문이다. 그래서 이 질문과, 그 답을 다시 보여주는 자리를
가장 신경 써서 다뤘다.

---

## 1. 질문 순서 (현재 구현, `app/app.js` STEPS)

```
인사(가격 안내) → 주문 시작
→ url(이미지 링크)
→ story(한 줄 이야기, 건너뛰기 가능)
→ size(사이즈)
→ [로그인 — 이름 질문 바로 앞]
→ name(이름)
→ phone(연락처)
→ address(배송 주소)
→ memo(배송 요청, 건너뛰기 가능)
→ confirm(확인 카드 + 개인정보 동의)
→ 접수 → 완료 화면(접수번호 + 한 줄 이야기 되돌려보기 + 목업 카드 + 결제 안내)
```

이 순서는 10-11 회의 결정과 10-15 이식 작업을 그대로 따른다. 이 문서는 순서를 바꾸지 않고,
각 자리의 문구만 다듬는다.

---

## 2. 단계별 안내 문구

### 인사 (`greet()`)
현재: `STANDARD · 뒷면 프린트 · 35,000원\n배송비 포함`
→ 변경 없음. 가격을 가장 먼저, 숨김없이 보여주는 지금 방식이 맞다. 손님이 "얼마인지도 모르고
대화를 시작하게" 만들지 않는다.

### 0) 주문 시작 버튼
현재: `주문 시작`
→ 변경 없음. 짧고 명확하다.

### 1) url — 이미지 링크
현재:
```
OWN STREET입니다.
생성한 이미지가 있는 채팅 링크를 보내주세요.
공개 링크만 받습니다.
```
→ **다듬은 문구** (반영함):
```
OWN STREET입니다.
만들어 둔 이미지가 있는 채팅 링크를 보내주세요.
공개 링크만 받을 수 있어요.
```
이유: "생성한"은 AI 툴 용어다. 선언문은 "어떤 AI 도구로 만들었는지 따지지 않는다"고 했으니,
손님에게 묻는 말에서도 도구 이름 대신 "만들어 둔"으로 낮춘다. "~받습니다"보다 "~받을 수 있어요"가
채팅 말투에 더 가깝다(이후 다른 질문들과 말투를 맞춤).

### 2) story — 한 줄 이야기 (핵심 질문)
현재:
```
이 이미지에 담은 생각이나 이야기를 한 줄로 알려주세요.
건너뛰어도 됩니다.
```
→ **다듬은 문구** (반영함):
```
이 이미지, 어떤 마음으로 만들었어요?
한 줄로 적어주면 접수번호 받을 때 같이 보여드릴게요.
건너뛰어도 괜찮아요.
```
이유:
- "담은 생각이나 이야기를 알려주세요"는 설명문 톤이라 질문처럼 느껴지지 않는다. "어떤 마음으로
  만들었어요?"는 실제로 묻는 말이고, 대답하기 더 쉽다(선언문의 "나다움을 발견하는지"를 질문
  난이도 쪽에서 낮춘 것).
- **이 질문에만 "왜 묻는지"를 먼저 알려준다** — "접수번호 받을 때 같이 보여드릴게요"를 질문
  문구 안에 넣었다. 이미지 링크·이름·전화번호 질문은 이유를 설명하지 않아도 손님이 바로 안다
  (주문에 필요하니까). 하지만 한 줄 이야기는 "이거 왜 물어보지, 꼭 써야 하나"라는 의문이 들 수
  있는 유일한 질문이라서, 대답을 어디서 다시 보게 되는지 미리 알려주는 게 "건너뛰어도 괜찮다"는
  말과 함께 있을 때 더 솔직하다. (대답을 보상처럼 포장하지 않으려 "같이 보여드릴게요"로 담백하게
  썼다. "특별하게 꾸며드릴게요" 같은 과장은 쓰지 않았다.)
- placeholder(`예) 처음으로 내가 정한 나의 색`)는 그대로 둔다. 선언문 어투와 잘 맞는 예시다.

### 3) size — 사이즈
현재: `사이즈를 골라주세요.` → 변경 없음.

### 로그인 안내 (`askLogin()`)
현재:
```
이제부터는 이름·연락처·주소를 여쭤봅니다.
접수 확인을 위해 Google 로그인이 필요합니다.
```
→ 변경 없음. "왜 지금 로그인이 필요한지"(개인정보 질문 시작 시점)를 이미 설명하고 있고, 과장
없이 정확하다. 10-11 회의에서 로그인 위치를 이름 질문 앞으로 정한 이유가 문구에도 그대로
드러나 있어 좋은 패턴이다 — story 질문 문구도 이 패턴("왜 지금 이걸 묻는지")을 따라간 것.

### 4) name / phone / address / memo
```
받는 분 이름을 알려주세요.
연락처를 알려주세요.
배송 주소를 알려주세요.\n상세 주소까지 적어주세요.
배송 요청사항이 있으면 적어주세요.
```
→ 변경 없음. 짧고 실용적인 지금 문구가 맞다. 이 네 질문은 "정보 수집"이 목적이라 이야기를
묻는 story 질문과 다르게 다룰 이유가 없다. 괜히 꾸미면 오히려 신뢰도가 떨어진다(목적이 다른
질문에 같은 어투를 쓰면 손님이 "왜 이름 물어보면서 감성적으로 말하지" 느낄 수 있다).

### 5) confirm — 확인 카드
현재 안내: `주문 내용을 확인해주세요.`
→ 변경 없음. 확인 카드 자체(각 항목 라벨 + 수정 버튼)가 10-16 디자이너 작업으로 이미 잘
정리돼 있다. 다만 카드의 "한 줄 이야기" 행도 다른 항목(이름, 사이즈 등)과 똑같은 모양으로
나온다 — 이건 이 문서가 다루는 "완료 화면에서 되돌려 보여주는 방식"과는 다른 자리이므로
confirm 카드는 그대로 "항목 중 하나"로 남겨두는 게 맞다고 본다 (수정하려면 다른 항목처럼
"수정" 버튼으로 고칠 수 있어야 하므로).

## 3. 접수 완료 화면에서 "한 줄 이야기" 되돌려 보여주기

### 지금 구현 (`showComplete()`, 10-15 developer가 이미 만들어 둔 자리)
```js
if (chat.data.story) done.append(el('p', 'done-story', '"' + chat.data.story + '"'));
```
접수번호 바로 아래, 작은 이탤릭체(`font-style: italic`, `color: muted-foreground`, 14px)로
따옴표에 묶여 조용히 한 줄 나온다. **자리는 이미 있다.** 이 문서가 제안하는 것은 그 자리에
붙는 "이름"과, 주변 문구뿐이다.

### 문제로 본 것
지금은 그냥 인용구처럼 조용히 붙어 있어서, 손님이 적은 한 줄이 "왜 여기 다시 나오는지"가
안 보인다. 접수 완료 화면의 중심은 접수번호와 결제 안내이고, 한 줄 이야기는 부가 설명처럼
묻혀 보인다. 선언문 기준으로 보면, 이 화면에서 가장 "그 사람다운" 요소가 가장 작게 다뤄지고
있는 셈이다.

### 제안 — 작은 라벨 하나 추가 (반영함)
`"한 줄 이야기" 인용구 위에 작은 라벨 한 줄을 붙인다:`
```
당신의 스트릿
"처음으로 내가 정한 나의 색"
```
- 라벨은 크게 꾸미지 않는다. 접수번호(`REQUEST COMPLETE`, 36px Anton)보다 한참 작게,
  지금의 `done-story`보다 한 단계만 더 눈에 띄게 — 딱 "이게 왜 여기 있는지"를 알려줄 정도로만.
- 라벨 문구로 "당신의 스트릿"을 고른 이유: 선언문의 핵심 문장 "자신만의 스트릿 하나를 갖는
  것"을 그대로 가져왔다. 서비스 이름(OWN STREET)과도 바로 연결되어서 새 용어를 만들지 않는다.
  "브랜드 스토리", "나의 이야기" 같은 말은 마케팅 용어로 들릴 위험이 있어 피했다.
- 손님이 story 를 건너뛰었으면 이 블록 전체(라벨 포함)가 보이지 않는다 — 지금 `if (chat.data.story)`
  조건을 그대로 쓰면 자동으로 그렇게 된다. 건너뛴 사람에게 빈 라벨을 보여주지 않는다.

### 반영한 코드 변경
`app/app.js` `showComplete()`:
```js
if (chat.data.story) {
  done.append(el('p', 'done-story-label', '당신의 스트릿'));
  done.append(el('p', 'done-story', '"' + chat.data.story + '"'));
}
```
`app/styles.css`:
```css
.done-story-label { margin-top: 14px; font-size: 11px; font-weight: 700; letter-spacing: 0.08em;
  text-transform: uppercase; color: var(--accent); }
.done-story { margin-top: 2px; font-size: 14px; font-style: italic; color: var(--muted-foreground);
  overflow-wrap: anywhere; }
```
(`.done-story` 의 `margin-top` 만 10px→2px로 줄여 라벨과 한 쌍처럼 붙게 했다. 디자인 시스템의
시그널 오렌지(`--accent`)를 라벨에 한 번만 좁게 썼다 — 접수번호·결제 버튼처럼 "중요한 행동"에
쓰는 색은 아니고, 작은 라벨 하나에만 쓰는 정도라 기존 "오렌지는 포인트로만" 규칙과 충돌하지
않는다고 판단했다.)

### 검토했지만 반영하지 않은 안
- **"공유하기" 버튼을 한 줄 이야기 옆에 붙이기**: 매력적이지만 "공유 링크"는 ROADMAP 의 더 뒤
  단계(브랜드 페이지·공유)이고, 지금은 접수번호·결제라는 이미 복잡한 화면에 새 버튼을 더
  얹는 셈이라 오늘 범위에서는 보류한다. 이후 "내 브랜드 페이지"가 생기면 그때 이 한 줄이
  그 페이지의 첫 줄이 되는 흐름을 그려볼 수 있다 (아래 "다음 제안" 참고).
- **story 를 건너뛴 손님에게 완료 화면에서 다시 물어보기**: 손님이 이미 "건너뛰기"를 선택한
  의사를 접수 완료 시점에 다시 거스르는 건 선언문의 "마지막 선택은 사용자가 한다"와 맞지 않다고
  봐서 제안하지 않는다.

## 4. 다음 제안 (이번 작업 범위 밖, 기록으로만 남김)

- 지금 `story` 는 손님이 입력한 그대로만 보여준다. 선언문이 말하는 "AI는 도구, 추천은
  출발점"을 이 질문에 적용한다면, 다음 단계는 손님이 한 줄을 적었을 때 "이 말을 브랜드 이름
  후보로 바꿔볼까요?"처럼 연결하는 것일 수 있다 — 이건 ROADMAP 의 "네이밍" 단계(6번)가
  맡을 일이고, 오늘은 묻지도 바꾸지도 않는다.
- 접수 완료 화면의 "당신의 스트릿" 한 줄이, 나중에 "내 브랜드 페이지"가 생기면 그 페이지로
  이어지는 첫 문장이 될 수 있다. 지금은 그 페이지가 없으므로 이 문서에서는 제안으로만 남긴다.
