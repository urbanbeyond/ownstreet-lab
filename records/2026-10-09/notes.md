# 저장소 밖에서 일어난 일 — Day 2 (기록 폴더 2026-10-09, 실제 시각은 한국 시간 2026-10-08 오전)

개인정보·주소·ID 는 적지 않는다.

## 의장이 한 일
- 09:41 보유 기간 문구를 "접수일로부터 1년"으로 정했다. (윤 개발자가 반영)
- 09:42 "실험실은 깃허브에 만들어 두었는데, 시트만 없는 것 아닌가" 하고 물었다. 확인해 보니 저장소는 있었지만 LAB 시트, LAB 서버, LAB 사이트가 없었다.
- 10:09 LAB 시트를 만들라고 하고, LAB 서버에 넣을 코드를 달라고 했다. 빈 시트 `ownstreetdb-LAB` 가 만들어졌고, 윤 개발자의 `backend/Code.gs` 가 그대로 전달됐다.
- 10:11 "붙여넣은 뒤 배포는 어떻게 하느냐"고 물었다.
- 10:14 배포한 LAB 주소를 알려 왔다. 이때 LAB 시트에는 아직 `REQUESTS` 탭이 없었다 (`setup` 을 실행하기 전이었다).
- 10:18 `setup` 을 실행했다. 실행 로그 그대로:
  - ✅ 스프레드시트 연결 완료: "ownstreetdb-LAB" 의 "REQUESTS" 시트 (이 스크립트가 붙어 있는 시트 사용 — 속성 SPREADSHEET_ID 는 아직 없음)
  - ✅ 머리글 13칸 확인: 접수번호 | 접수시간 | 이메일 | 이름 | 전화번호 | URL | 상태 | 사이즈 | 주소 | 배송 요청 | 한 줄 이야기 | clientRef | 동의 시각
  - ✅ Firebase API 키 확인 완료 (로그인 확인 기능 정상)
- 10:18 Apps Script 프로젝트 제목이 "제목 없는 프로젝트"인데 괜찮으냐고 물었다. 작동에는 영향이 없고, 실제 서버와 헷갈리지 않게 이름을 바꿔 두길 권했다.
- 10:20 LAB 주소를 열어 나온 응답을 그대로 알려 왔다:
  `{"ok":true,"service":"OWN STREET","version":2,"ready":true,"storage":true,"message":"접수 서버가 작동 중입니다."}`

## 이것으로 처음 실제 환경에서 확인된 것
- 윤 개발자의 서버 v2 가 실제 구글 서버에서 뜬다 (`doGet` 응답).
- 빈 시트에 `REQUESTS` 탭과 머리글 13칸이 만들어진다.
- 시트에 붙은 스크립트는 스크립트 속성 없이도 그 시트를 쓴다.

## 아직 확인되지 않은 것
- 실제 주문 요청(`doPost`)은 한 번도 들어가지 않았다. 옛 형식도, 새 형식도.
- LAB 사이트가 없어서 시험 주문을 넣을 화면이 없다.
- 실제 주문 시트와 실제 서버는 건드리지 않았다. 머리글은 예전 7칸 그대로다.
